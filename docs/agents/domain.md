# Domain docs

This is a single-context repo. Read root `CONTEXT.md` before exploring the code and read relevant decisions in root `docs/adr/`.

Use the glossary’s terms in issues, proposals, hypotheses, and test names. Avoid synonyms that `CONTEXT.md` explicitly rejects.

If a needed term is missing, reconsider the term or note the gap for `/domain-modeling`. Surface conflicts with an ADR explicitly rather than silently overriding it.

If a referenced domain file is absent, proceed without proposing one upfront; `/domain-modeling` creates domain docs when decisions are resolved.
