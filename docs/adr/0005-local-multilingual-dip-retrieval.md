# Use local multilingual embeddings for DIP retrieval

Add semantic retrieval over DIP proceeding summaries, step text, and processed document text using Qwen3-Embedding-0.6B served locally by optional Ollama, with vectors stored in PostgreSQL through pgvector. This keeps the first retrieval system self-hosted and reuses the existing database; the trade-off is operating local model and vector-search infrastructure. Keep metadata import independent from model and PDF processing: summaries and step text use durable embedding jobs, while linked PDFs are fetched lazily for the 14-day hot subset or on demand, extracted with PyMuPDF, and cached by document ID and byte hash. Retain fetched byte variants indefinitely, subject to source permissions. Search only the latest record text version and return source references; answer generation and news-to-proceeding links remain deferred.
